Shape

One provider per thing; usePartyPlaya is the only file that knows both the room and Playa.

Context or props

Context when…

  • it's the thing itself, read at many depths: room, layout, Playa
  • the reader only makes sense inside that thing: regions, layers, Playa parts
  • it's passed through a component that doesn't use it

Props when…

  • it's one level down, or a leaf that could live anywhere: UiAvatar
  • it's the parent's intent: onClose, onInvite, onLineClick
  • it's a helper or view you want to test without a provider

// Wires Playa to the room. The only file that knows both.
export function usePartyPlaya(party: AppParty) {
  const user = useAuthUser()
  const { sidebar, activityLevel } = useWatchLayout()
  const syncState = useSyncStateMutation(party.id)
  const channel = `private-party.${party.id}`

  const playa = usePlaya({
    src: party.video.video_url,
    initialTime: party.current_time,
    subtitles: party.video.subtitle_url,
    onPlayback: ({ time, isPlaying }) => syncState.mutate({ current_time: time, is_playing: isPlaying }),
    // Today's send from use-reactions; Pusher doesn't echo client events, Playa already floated yours.
    onReact: (emoji) => {
      const room = pusher()?.channel(channel)
      if (room?.subscribed) room.trigger(REACTION_EVENT, { userId: user.id, emoji })
    },
  })

  usePusher(channel, 'state', ({ state }) => playa.sync({ time: state.current_time, isPlaying: state.is_playing }))
  usePusher(channel, REACTION_EVENT, ({ userId, emoji }) => {   // REACTION_EVENT lives here now
    const by = toPlayaPerson(party, userId)   // name from the party, not the payload
    if (by && isReaction(emoji) && showsReactions(activityLevel, sidebar !== 'closed')) playa.react(emoji, { by })
  })
  usePusher(channel, 'log', ({ log }) => {
    if (sidebar === 'closed' && showsOnOverlay(activityLevel, log)) playa.activity(toPlayaActivity(log))
  })

  return playa
}

export interface PlayaOptions {
  src: string
  initialTime?: number
  subtitles?: string | null
  onPlayback?(state: { time: number; isPlaying: boolean }): void   // yours only
  onReact?(emoji: string): void                                     // yours only, i.e. no `by`
}

export function usePlaya(options: PlayaOptions): Playa {
  const $video = useRef<HTMLVideoElement>(null)
  const [state, dispatch] = useReducer(reducer, initialState(options))
  // ...

  // Applies a move; only yours reach the callback.
  function move(next: { time: number; isPlaying: boolean }, mine: boolean) {
    dispatch({ type: 'move', payload: next })
    $video.current!.currentTime = next.time
    if (mine) options.onPlayback?.(next)
  }

  return {
    state,
    play: () => move({ time: state.time, isPlaying: true }, true),
    seek: (time) => move({ time, isPlaying: state.isPlaying }, true),
    sync: (next) => move(next, false),
    // pause, skip, volume, react, activity ...
  }
}

ui/src/screens/app.watch.home/app-watch-home-activity/app-watch-home-activity-to-playa.ts new
// The room's words → Playa's. Unknown or old kinds fall back to the server's text.
export function toPlayaActivity(log: AppPartyLog): PlayaActivity {
  if (log.type === 'message') return { id: String(log.id), type: 'message', by: person(log.message.user), text: log.message.text }
  const { kind, meta, user, text } = log.activity
  switch (kind) {
    case 'paused': return { id: String(log.id), type: 'paused', by: person(user), at: meta?.seconds }
    case 'seeked': return { id: String(log.id), type: 'seeked', by: person(user), from: meta?.from_seconds, to: meta?.seconds ?? 0 }
    case 'joined_code': return { id: String(log.id), type: 'joined', by: person(user), via: 'code' }
    // ... played, joined, switched
    default: return { id: String(log.id), type: 'note', by: person(user), text }
  }
}

Decisions

What does Playa own?

The <video> only
Video, reactions, activity lines, subtitles; the app feeds them
They're all things on the picture; Playa owns how they look and expire.

What playa.activity() takes

A rendered content node
Loose { id, type, metadata }
Typed per type; Playa renders it
One look and one copy everywhere; a typo in a field is a type error.

Yours vs theirs

Callbacks for yours; sync() and { by } for theirs
A wrapper that re-implements play/seek
Playa subscribes to Pusher
One rule, and Playa never learns where moves come from.

How many contexts?

One per thing: Room, Layout, Playa
A page grab-bag (useWatchPage)
One per rate of change
Each name says what it is; perf is good enough.

Episode picker and shortcuts

One AppWatchHomeSheets wrapper
The two existing modals, each in the page tree
Being modals doesn't make them one thing; the page should name both.

Names and home

Flat PlayaSlider in components/playa/
Playa.Slider namespace
Repo rule: named exports named after their file.

Adopt a real library?

Hand-rolled Playa, shaped like Media Chrome / Vidstack
Adopt one
The server decides playback; a library's own store would fight sync().

Layout state

sidebar + modal enums
Today's five booleans
Hotkeys turn off with a single check: modal !== null.

Risks

HighEcho loop: a synced move posts back to the room.
sync() never calls onPlayback; a test pins it.
MedControls timing (5s hide, menu pin, volume, tooltip count) drifts.
Overlay exposes a pin; compare ⅛-speed recordings before and after.
MedParallel edits in ui/ collide with the moves.
Moves land alone in phase 4; stage only these files.
LowActivity extras (typing dots, level toast) don't fit playa.activity().
They stay app layers, slotted next to PlayaActivity.
